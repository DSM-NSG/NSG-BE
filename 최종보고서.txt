1. 개요 및 목표

가. 프로젝트 기획 의도

  대덕소프트웨어마이스터고 신입생들은 학교 생활, 기숙사, 주변 시설, 전공 학습에 대한
  정보가 부족해 초기 적응에 어려움을 겪는다. 기존에는 선배를 통한 구두 전달이나
  실명 기반 디스코드에 의존하는 구조였다.

  NSG는 이 문제를 해결하고자 기획된 재학생 전용 정보 공유 플랫폼이다.
  DSM 계정 기반 인증으로 신뢰도 높은 폐쇄형 커뮤니티를 구성하고,
  장소 공유, 꿀팁 게시판, 전공 Q&A 기능으로 학생 간 정보 교환 문화를 형성하는 것을 목표로 한다.

나. 최종 요구사항 및 기능 명세

  - 회원 인증: DSM 계정 기반 로그인, JWT 발급
  - 꿀팁 공유: 게시글 작성/조회/삭제, 카테고리 필터
  - 장소 공유: 좌표 등록, 카테고리별 지도 표시, 네이버지도 연동
  - 전공 Q&A: 전공 태그 기반 게시글, 인기 태그 랭킹
  - 댓글/대댓글/좋아요: 계층형 댓글, 익명 번호 부여
  - 이미지 업로드: AWS S3 저장
  - 익명 기능: 게시글/댓글 익명 작성, 게시글 내 순번 부여
  - 회원탈퇴: 소프트 삭제 + 개인정보 초기화

나. 주요 기능 구현 내역

  기능 1: 재학생 인증 기반 로그인

  ▪ 구현 내용:
    DSM 학교 계정으로만 로그인 가능하다. 로컬 DB에 계정이 있으면 비밀번호를
    검증하고, 없으면 DSM 외부 API를 호출해 인증 후 User를 자동 생성한다.
    인증 성공 시 access token(30분)과 refresh token(7일)을 발급한다.

  ▪ 결과 화면:
    [login_swagger.png]

  ▪ 예외 상황 처리:
    - 비밀번호 불일치 또는 DSM API 인증 실패: 401 Unauthorized
    - 필수 필드 누락: 400 Bad Request
    - 탈퇴 계정: 401 Unauthorized (SimpleJWT의 is_active 체크)

  기능 2: 꿀팁 공유 게시판

  ▪ 구현 내용:
    카테고리(장소/기숙사 생활/대마고 생활/기타)로 분류된 게시판이다.
    사진 첨부, 익명 작성, 좋아요, 댓글/대댓글 기능을 지원하며
    장소 태그 시 지도와 연동된다.

  ▪ 결과 화면:
    [tip_list_swagger.png]
    [tip_create_swagger.png]

  ▪ 예외 상황 처리:
    - 미인증 작성: 401 / 타인 삭제: 400 / 없는 게시글: 404

  기능 3: 장소 공유 및 지도 연동

  ▪ 구현 내용:
    학교 주변 장소를 위도/경도 좌표와 네이버지도 링크와 함께 등록한다.
    카테고리: 맛집, 카페, PC방, 노래방, 기타.
    특정 장소에서 작성된 꿀팁만 모아보는 장소별 게시글 조회 기능도 제공한다.

  ▪ 결과 화면:
    [place_list_swagger.png]

  ▪ 예외 상황 처리:
    - 미인증 등록: 401 / 타인 삭제: 400 / 잘못된 카테고리: 400

  기능 4: 전공 생활 게시판 및 인기 태그

  ▪ 구현 내용:
    전공별 질문·지식 공유 게시판이다. 게시글에 여러 전공 태그를 달 수 있으며,
    좋아요 수와 시간 감쇠를 고려한 점수 공식으로 인기 전공 태그 Top N을 반환한다.
    점수 공식: score = Σ (1.0 + like_count × 2.0) × 1 / (1 + 경과일수 × 0.1)

  ▪ 결과 화면:

  ▪ 예외 상황 처리:
    - 중복 전공 등록: 400 + "이미 존재하는 전공입니다."
    - major_ids 미포함: 400


3. 서비스 연동 및 데이터 처리

가. 외부 서비스 연동 내역

  - DSM 외부 API: 재학생 계정 인증 (HTTP POST 요청)
  - AWS S3: 이미지 파일 저장 (boto3 SDK)
  - AWS EC2 (Ubuntu): 서비스 배포 서버 (SSH + Docker + docker-compose)
  - PostgreSQL: 메인 데이터베이스 (psycopg2-binary)

  DSM API 연동: 로그인 시 로컬 계정이 없으면 DSM API를 호출해 학생 정보를 받아
  User를 자동 생성하고, 기수(cohort)는 서버에서 입학 연도 기반으로 계산한다.

  S3 연동: POST /images/upload/로 이미지를 전송하면 서버가 S3에 저장 후
  URL을 반환한다. 게시글 작성 시 해당 URL을 image_urls에 포함하면 PostImage
  테이블에 순서(order_index)와 함께 저장된다.

나. 데이터 처리 방법

  View → Service → Model 레이어드 아키텍처를 채택해 비즈니스 로직을 service
  레이어에 집중시켰다. 주요 처리 방식은 다음과 같다.

  - 익명 번호: PostAnonymousUser 테이블에 (post, user) → anonymous_number 매핑 저장.
    select_for_update + transaction.atomic으로 동시 요청 시 번호 중복 방지.
  - 좋아요 카운터: F() 표현식으로 DB 레벨 원자적 증감 처리해 race condition 방지.
  - 이미지 순서: order_index 필드로 첨부 순서 보장.

    기능 수정 시 테스트 먼저 실행해 회귀 여부 확인.
  - 배포 업데이트: git pull → docker-compose up -d --build 순서로 반영.
    컨테이너 시작 시 마이그레이션 자동 실행.
  - 데이터 보존: 회원탈퇴 시 소프트 삭제(is_active=False + PII 초기화)로
    기존 게시글/댓글은 "알 수 없는 사용자"로 표시하며 보존.
