2. 전공 카테고리 생성 API

  관리자가 전공을 등록하는 API를 추가했다.
  중복 전공명 등록 시 400 에러를 반환한다.

  POST /majors/create/
  Authorization: Bearer <token>
  Body: { "name": "백엔드" }
  Response 201: { "id": "uuid", "name": "백엔드" }
  Response 400: { "name": ["이미 존재하는 전공입니다."] }

  DRF는 source='major'처럼 필드명이 모델 필드명과 다를 때
  UniqueValidator를 자동으로 붙이지 않는다.
  명시적으로 validators=[UniqueValidator(...)]를 선언해 해결했다.

3. 인기 전공 태그 Top N API

  전공별 인기도를 점수화해 상위 N개를 반환한다.

  GET /majors/popular/
  Response: [
    { "id": "uuid", "name": "백엔드", "post_count": 12, "total_likes": 45, "score": 8.3 },
    ...
  ]

  [점수 공식]
  score = Σ (1.0 + like_count × 2.0) × 1 / (1 + 경과일수 × 0.1)

  게시글이 없는 전공도 score=0으로 포함해 항상 전체 전공 목록을 반환한다.
  Major.objects.all()을 먼저 로드해 dict로 초기화한 후 MajorTag 루프로 점수를 누적하는 방식.

4. 회원탈퇴 API

  유저 행을 실제 삭제하지 않고 소프트 삭제 방식으로 구현했다.

  [설계 이유]
  Post, Comment, Place 등 author FK가 SET_NULL이므로
  실제 삭제 시 작성자 정보가 모두 null이 되어 콘텐츠 맥락이 사라진다.
  대신 PII(개인식별정보)만 초기화하고 is_active=False로 접근을 차단한다.

  [처리 내용]
  - is_active = False              → JWT 인증 즉시 차단 (SimpleJWT가 is_active 체크)
  - name = "알 수 없는 사용자"     → 기존 게시글에 표시되는 이름 익명화
  - account_id = None
  - student_id = "withdrawn_{uuid}" → unique 제약 유지하며 원래 학번 해제
  - password_hash = unusable        → 비밀번호 무효화

  DELETE /users/me/withdraw/
  Authorization: Bearer <token>
  Response: 204 No Content

5. Docker / docker-compose 배포 환경 구성

  다음 주 EC2 배포를 위한 Docker 환경을 구성했다.

  [구성 내용]
  - Dockerfile: Python 베이스 이미지, requirements 설치, Gunicorn 실행
  - docker-compose.yml: web(Django+Gunicorn) + nginx 컨테이너 구성
  - entrypoint 스크립트: 컨테이너 시작 시 자동 migrate 실행
  - 환경변수: .env 파일로 분리 (DB, AWS, SECRET_KEY 등)
  - psycopg2-binary: PostgreSQL 드라이버를 binary 패키지로 변경 (빌드 의존성 제거)
  - ALLOWED_HOSTS: 배포 서버 IP 추가

  로컬에서 docker-compose up으로 정상 동작 확인 완료.


■ 이슈 관리 및 해결 과정

[이슈 1] MajorCreateSerializer UniqueValidator 미동작

  - 발생한 이슈:
    전공 이름 중복 등록 시 DB IntegrityError가 발생했다.
    Serializer 레벨에서 400을 반환해야 하는데 500이 반환됐다.

  - 원인 분석:
    DRF ModelSerializer는 필드명(name)과 모델 필드명(major)이 다를 때
    UniqueValidator를 자동으로 추가하지 않는다.

  - 해결 과정 및 결과:
    validators=[UniqueValidator(queryset=Major.objects.all(), message="이미 존재하는 전공입니다.")]
    를 필드에 명시적으로 선언해 Serializer 레벨에서 중복 검증 처리.

[이슈 2] psycopg2 빌드 오류

  - 발생한 이슈:
    Docker 이미지 빌드 중 psycopg2 컴파일 오류 발생.

  - 원인 분석:
    psycopg2는 C 확장 빌드 시 libpq-dev 등 시스템 패키지가 필요한데
    베이스 이미지에 설치되어 있지 않았다.

  - 해결 과정 및 결과:
    psycopg2를 psycopg2-binary로 변경해 사전 컴파일된 바이너리를 사용.
    빌드 의존성 없이 설치 가능해 해결.
